# 二、当前定稿模型

最终网络固定为：

```text
Image + Prompt
      │
      ├──────────────────────────────┐
      ↓                              ↓
  CLIP RN50                      CLIP Text
      │                              │
      ↓                              │
Spatial Feature F                    │
[B,2048,H,W]                         │
      │                              │
      ├──── Original IP-IQA ─────────┘
      │            ↓
      │     Cross-modal Feature
      │            ↓
      │          q_base
      │
      └──── Local Quality Branch
                   ↓
             1×1 Conv
            2048 → 256
                   ↓
              Fine / Coarse
               双尺度特征
                /       \
               ↓         ↓
          Channel     Channel
          Attention   Attention
               ↓         ↓
          Spatial     Spatial
          Attention   Attention
               \         /
                \       /
                 ↓     ↓
            Cross-Branch
             Attention
             Fine ↔ Coarse
                  ↓
           Multi-Scale Fusion
                  ↓
          Residual Refinement
                  ↓
          Patch Score Head
                 +
          Patch Weight Head
                  ↓
               q_local
                  │
            q_base + q_local
                  ↓
             Gated Fusion
                  ↓
            Final Quality
```

来源关系固定为：

```text
IP-IQA
→ 整体跨模态主框架

MS-SCANet
→ 多尺度
→ Channel Attention
→ Spatial Attention
→ Cross-Branch Attention

AM-BQA
→ Patch Score
→ Patch Importance Weight
→ Weighted Aggregation
```

# 三、为什么正式实验不再只跑 30 epoch

当前 20/30 epoch 的实验本质上属于：

```text
快速验证
```

作用是判断：

```text
模块值得不值得继续
```

而不是最终论文式训练。

IP-IQA 官方 AGIQA-3K 配置为：

```text
input_resolution = 512

batch_size = 32

batch_size_val = 32

max_epoch = 100

init_lr = 1e-5

weight_decay = 0

freeze_text = True

qa_token = True
```

官方代码：

https://github.com/Coobiw/IP-IQA/blob/master/ipiqa/projects/agiqa3k/ipiqa.yaml

因此我们的正式训练预算向：

```text
100 epoch
```

看齐是合理的。

另外，不同 AGIQA 工作使用的训练轮数本来就不完全相同。

例如 IPCE 官方 AGIQA-3K 训练脚本：

```text
epoch = 30
batch = 32
lr = 5e-6
```

代码：

https://github.com/pf0607/IPCE/blob/main/train_aigc_agiqa3k.py

而近期 DCMPLN 使用：

```text
50 epoch
batch = 64
224×224
lr = 1e-4
10 repeated runs
```

论文：

**A Deep Cross-modal Prompt Learning Network for Artificial Intelligence Generated Image Quality Assessment**

Displays, 2026, Vol. 91, 103208

DOI：

https://doi.org/10.1016/j.displa.2025.103208

所以：

```text
30 epoch 并不是错误
```

只是对于我们这种：

```text
CLIP backbone
+
新增随机初始化 MSDA
```

正式结果更建议给到充分训练预算。

# 四、AGIQA-3K 正式训练：推荐 100 epoch 总预算

## 4.1 推荐采用两阶段训练

我们已经验证：

```text
Weighted Local
→ 再加入 MSDA
```

比从头同时训练所有新增模块更稳定。

所以正式版继续保留这个训练策略。

### Stage A：Local Warm-up

```text
20 epoch
```

网络：

```text
IP-IQA
+
Projection
+
Patch Score
+
Patch Weight
+
Gated Quality Fusion
```

暂时不启用：

```text
Channel Attention

Spatial Attention

Cross-Branch Attention
```

---

### Stage B：Full Model

从 Stage A checkpoint 初始化：

```text
80 epoch
```

启用：

```text
Multi-Scale

Channel Attention

Spatial Attention

Cross-Branch Attention

Residual Multi-Scale Fusion
```

总训练预算：

```text
20 + 80
=
100 epoch
```

这样既保持当前已验证的 warm-start 方式，又与 IP-IQA 官方 100 epoch 训练规模一致。

# 六、正式分组学习率

继续沿用已经验证有效的 Adjustment 2：

```text
IP-IQA / pretrained backbone
LR = 1e-5
```

```text
E1 inherited local branch
Projection
Score Head
Weight Head

LR = 3e-5
```

```text
New MSDA blocks
Channel
Spatial
Cross-Branch
Scale Fusion

LR = 1e-4
```

```text
Refine Gate
Outer Local Gate

LR = 1e-4
```

原因非常清楚：

```text
Pretrained part
→ 小 LR

Random initialized new module
→ 大 LR
```

不要再回到：

```text
所有参数统一 1e-5
```

# 八、是否应该直接跑 120 / 150 / 200 epoch

第一版不建议。

先跑：

```text
100 epoch total
```

观察 validation。

如果：

```text
epoch 70~100
validation 已经平台化
```

没有理由继续。

如果：

```text
epoch 100 时
quality SRCC / PLCC 仍然连续明显上升
```

以后正式论文阶段再考虑延长。

当前不要提前预设：

```text
epoch 越多越好
```

# 九、一个比继续增加 epoch 更重要的修改：保存 Quality Best

当前模型同时预测：

```text
Quality

Alignment
```

而现有 trainer 的 best checkpoint 偏向：

```text
joint aggregate
```

这已经出现过：

```text
某 epoch 的 Quality 更强
但因为 Alignment 略低
没有被保存为最终 best
```

所以正式训练建议一次保存三个 checkpoint：

```text
checkpoint_best_joint.pth

checkpoint_best_quality.pth

checkpoint_best_alignment.pth
```

# 十九、MOS 尺度建议

AIGCIQA2023 的 MOS 使用：

```text
0 ~ 100
```

建议训练前：

```python
quality = quality / 100.0

correspondence = correspondence / 100.0
```

让回归值落到：

```text
0 ~ 1
```

更接近当前训练数值尺度。

相关系数：

```text
SRCC
PLCC
KROCC
```

不会因为这种线性缩放改变本质排序关系。

# 二十三、正式自身消融怎么设计

最终不要放以前失败的旧 Transpose Attention。

只保留能构成方法逻辑的三行。

| Model | Weighted Local | MSDA | 含义 |
|---|---:|---:|---|
| IP-IQA | × | × | 基础跨模态模型 |
| + Local Weighting | ✓ | × | 增加局部 patch 质量聚合 |
| **Full Ours** | ✓ | ✓ | 加入多尺度双注意力局部增强 |

结构逻辑：

```text
IP-IQA
↓
显式 Local Quality
↓
Multi-Scale Local Refinement
```

这就足够。

# 三十六、不要把不同协议的文献数字当成完全公平排名

这是最终写作里一定要注意的。

例如 DCMPLN：

```text
224 input
batch 64
50 epoch
10 runs
```

我们：

```text
512 input
batch 32
100 epoch total
固定 grouped split
```

因此即使最终：

```text
Ours = 0.875

某文献 = 0.870
```

也不能直接说：

```text
在完全公平条件下超过 0.005
```

更安全的表达：

> “在我们的实验协议下，所提出方法取得 X；与已有文献报告的代表性方法结果相比，性能具有竞争力。”

真正公平、最有说服力的是：

```text
Our reproduced IP-IQA
vs
Our Full Ours
```

# 四十五、最终方法与实验一句话版本

方法：

> 以 IP-IQA 为跨模态基础框架，在 CLIP 空间视觉特征上构建多尺度局部质量分支，通过通道注意力、空间注意力和跨尺度交互增强局部失真表示，并结合 patch-wise quality score / importance weight 得到局部质量估计，最终与 IP-IQA 全局质量预测进行门控融合。

实验：

> 在 AGIQA-3K 和 AIGCIQA2023 两个独立 AIGC-IQA 数据库上进行验证；正式训练采用 512 输入、batch 32 和 100 epoch 总训练预算，并使用 SRCC、PLCC 和 KROCC 评价质量预测性能；外部比较方法优先采用已有近期论文统一报告的 literature-reported results，同时使用我们自行训练的 IP-IQA 作为最主要的公平内部 baseline。
